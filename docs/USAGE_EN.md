# ResearchStarterKit Usage Guide (English)

[Home](../README_EN.md) | [中文指南](USAGE.md)

## 1. Download the project

Open the GitHub repository page and choose **Code → Download ZIP**, then extract it to a local folder. Alternatively, clone the repository with Git. Read the README and inspect the actual application files and dependencies.

**If you downloaded only this README documentation package**, copy `README.md`, `README_EN.md`, and the `docs/` directory into the actual Git repository root; this package does not include the application source.

## 2. Launching the local application

The exact startup command, dependency versions and URL **cannot be verified without the real source code**, so this package does not invent them. Before publishing, the maintainer should test and document:

- Supported operating systems and required Python/Node.js versions
- Exact dependency installation command
- Exact launcher or startup command
- Browser address and port, if applicable
- Location and backup of user data
- Whether any API keys, internet connection or external services are necessary

Verify all steps from a fresh download on a clean machine.

## 3. A four-week beginner reading workflow

**Week 1 — Scope a topic:** State one learning question, make a keyword list, and begin with review papers or foundational work.

**Week 2 — Read systematically:** For each paper record its title and source, research problem, method, evidence, limitations, and unanswered questions. Skim abstract, introduction, figures and conclusion before deciding which sections need careful reading.

**Week 3 — Compare studies:** Compare several related papers by assumptions, methods, experimental settings, evidence and limitations. Do not simply collect summaries.

**Week 4 — Synthesize and plan:** Write a short topic review covering what is established, what is disputed, and what to learn or test next. Repeat this process weekly.

## 4. Using the learning materials

Use **research methodology** materials to challenge your research questions and evaluate evidence; **academic writing** materials to construct a coherent argument; and **AI model slides** to progress from concepts to examples, model structure, experiments and self-explanation. Materials may be added gradually; check which files actually exist in the repository.

## 5. Privacy and troubleshooting

Local-first does not imply completely offline. External services may transmit data. Keep private notes, licensed PDFs, API keys, configuration secrets and user databases out of public commits.

To report a problem, open a **GitHub Issue** with your operating system, reproducible steps, expected behavior and actual behavior. Do not include sensitive files or credentials.
